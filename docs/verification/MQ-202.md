## Contract and boundary

The native user-authenticated Admin `POST /admin/supplier/imports` accepts `{supplierId,idempotencyKey,csv}` and `GET /admin/supplier/imports/:id` returns a sanitized run. A 512 KiB route parser limit bounds the JSON envelope. CSV is limited to 256 KiB, 100 rows and 1 KiB per record; exact headers, quoted fields, ASCII SKUs, integer quantities and real UTC timestamps are checked before commerce writes. The backend directly declares the already pinned `csv-parse` 7.0.2; no new parser version or external service was introduced. Responses contain only run ID, status, counts, timestamps and bounded error codes/rows; raw CSV is not retained in workflow state or returned in audit responses.

PostgreSQL enforces supplier/key uniqueness and one active import per supplier. Identical key and digest replay the prior run; changed bytes conflict. The single permitted demo target is the seeded supplier pouch. `fictional-north` owns a native stock location outside the Store sales channel. Initial associations use the MQ-201 mapping workflow, and stock changes use native Medusa inventory workflows while holding the same inventory-item locks used for reservations. An audit journal records intended work and prior state. Successful observations publish together only after the native writes finish. Failed writes invoke workflow compensation; uncertain ownership or a lost lock retains the supplier claim in reconciliation. The eligibility helper uses injected time and a configurable positive threshold, defaulting to 15 minutes; it fails closed on stale, future, unavailable, failed, pending or reconciling data and preserves the last good observation.

## Reconciliation and limits

A running or reconciliation run retains its database claim and makes affected eligibility fail closed. Stop every importer/worker for the supplier and confirm the original process has exited before recovery. On a verified disposable or otherwise authorized environment, inspect the run and its journal privately; do not paste CSV, identifiers or credentials into logs or a ticket. Set `MQ202_RUN_ID` to the run ID and invoke `pnpm --dir apps/backend exec medusa exec ./src/scripts/reconcile-supplier-import.ts`. The command reacquires native inventory locks, reverses only journaled, verifiable writes, and returns a sanitized status. If stock, reservations, a pending write or a link cannot be attributed safely, it leaves the run in reconciliation and the claim held. In that case preserve the journal and escalate to Sol; do not clear the claim or edit commerce tables as a shortcut.

The supplier location must remain outside all Store sales channels. Operators must not independently change that location while an import or its recovery is active: native Admin stock updates do not all acquire the reservation lock. The importer cannot prove ownership of an ambiguous in-flight write after a crash or lease loss; it deliberately stops for reconciliation. Freshness is evidence for a later gate, not a checkout guarantee. Supplier checkout, durable retries, Admin UI, real suppliers and deployment remain separate work.
