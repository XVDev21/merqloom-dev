## Store and API contract

The catalog asks which fictional object fits. Product pages answer with native dimensions, material, finish, Philippine demo price, channel inventory and fixture fulfillment source. Studio and roadmap now describe catalog search and variant browsing as available. Cart and checkout are reserved for MQ-103.

| Operation | Medusa 2.23 contract |
| --- | --- |
| Browse collections | `GET /store/collections` returns native ID, handle and title. The control lists up to the first 100 collections ordered by title. |
| Search and filter | `GET /store/products` uses native `q`, optional `collection_id[]`, handle ordering, offset and 12 results per page. Live probes matched title, description and variant SKU. No separate index, special fuzzy search, or search across product specs is asserted. Queries are trimmed and limited to 100 characters. Page navigation caps at 10,000. |
| Select a product | `GET /store/products` filters by handle and asks for native product and variant fields. `GET /store/regions` resolves the PHP region containing the Philippines. |
| Read price and stock | The server supplies `region_id` for `variants.calculated_price` and requests `variants.inventory_quantity`. The installed Medusa handler computes availability for the one sales channel linked to the demo publishable key. The key stays server-side. |
| Restore state | `/store?q=desk+tray&collection=desk-organization` keeps filters. `/store/desk-tray?variant=<native variant ID>` restores the exact finish with optional catalog context. Missing IDs or IDs that belong to another product show recovery choices and no price for a different finish. |

Native inventory is presented as demo availability. The supplier pouch is a browse-only preview. No price or stock is invented when a native response lacks those fields. A network or API error offers a fresh reload of the current catalog or selected product URL. Next streaming can return HTTP 200 with the visible product-not-found state if the response shell has already been sent.
