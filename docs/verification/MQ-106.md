## Startup diagnosis

The first `docker compose up -d --no-build --no-recreate --wait --wait-timeout 360` against the disposable project exited 1: the backend reported `MQ106_MIGRATION_FAILED` and the storefront did not start. A one-off reproduction captured only a fixed diagnostic classification: Medusa's migration connection timed out. The independent PostgreSQL readiness query had succeeded. Inspection of the installed Medusa 2.23.0 `load-module-database-config.js` showed that a Compose hostname is classified as remote and defaults to TLS unless the URL disables it; local PostgreSQL does not offer TLS. Repeating the same disposable migration with only `?sslmode=disable` added to its connection URL exited 0 and created the native schema (152 public tables including the synthetic probe). The local Compose URL now specifies that setting; production runtime URLs remain supplied by the operator. The diagnostic run did not print credentials or raw errors.
