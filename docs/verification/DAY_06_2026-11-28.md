## Contract and scope

The selected native variant is validated against its product, direct-stock metadata, price and current channel availability before mutation. Quantity changes and removal update Medusa's cart. The supplier pouch remains browse-only, and the MQ-102 invalid-finish placeholder and recovery are preserved. The Philippine region and channel are resolved server-side; item subtotal, shipping, tax and total come from Medusa. A zero shipping amount is displayed when a shipping method exists.

The Store issues an opaque, HttpOnly, SameSite=Lax session cookie, secure by default except for the explicit loopback HTTP start. Redis stores only the cart reference, completion phase and a minimal confirmation summary, with a 30-day expiry. Contact and address fields are held in the native cart/order, not in the Redis session; the form asks for fictional data. Server-side validation checks email, names, street, city and a four-digit PH postal code. Javascript keeps valid input in place while correcting an invalid field; the server validates again. Review, submit and confirmation disclose that payment and shipping are simulated. The native payment session amount is checked against the final cart total.

Cart mutations and completion use a per-session Redis lock. The `completing` phase is saved before the native completion call. A timeout, in-progress conflict, or ambiguous retry retains the cart and blocks edits/reset; a retry uses the same cart. A confirmed Medusa order alone creates the session-bound confirmation. The confirmation exposes no address, email, cart ID or session token. Cross-origin form submissions are rejected. Native Medusa remains authoritative for order creation and inventory; no payment, fulfillment or provider redesign was added.
