# ADR-005 · Local infrastructure

Accepted November 22; amended for MQ-106. Project `merqloom-dev` owns its Compose network, PostgreSQL 16 database, Redis 7, and development app services. Bind PostgreSQL to loopback 15432, Redis to 16379, Studio/Store to 18000 and backend/Admin to 19000. Keep the existing PostgreSQL and Redis volume identities and mount paths. Leave unrelated Docker projects and the global context alone. Physical checkout on this workstation is `~/merqloom-dev`.

`make start` is the primary local creation and startup path; existing containers can subsequently be started from Docker Desktop. Development containers wait for dependencies, run the existing idempotent migration and demo-seed path, and bind app source for hot reload. The data-only Compose services and host app commands remain an alternative. Tests that create orders use explicitly disposable projects and data. The [local runbook](../architecture/LOCAL_ENVIRONMENT.md) documents both paths and their port conflicts.

The Compose development stack sets a loopback-specific cookie override and publishes only to `127.0.0.1`. Separate multi-stage production images receive connection settings and secrets at runtime, retain framework cookie defaults, and do not initialize demo data as their default command. The M0 configuration supplies Redis connectivity. M2 must configure and demonstrate durable workflow processing separately. Deployment, paid services and public application hosting are outside the MVP.
